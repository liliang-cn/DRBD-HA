## 1. Module: LVM Storage Pool Management (✅ Implemented)

### 1.1 Overview
Transforms physical disks into flexible logical volume groups, allowing multiple isolated HA services to share the same physical storage backend.

### 1.2 Implementation Details
- **Core Logic:** `src/core/storage/` (LvmProvider)
- **Models:** `src/models/storage.rs`
- **Features:**
    - `StoragePool` (LVM Volume Group) creation and listing.
    - `Volume` (LVM Logical Volume) creation.
    - **Safety:** Automatic `lvm.conf` filter management to prevent LVM from scanning DRBD devices (critical for avoiding recursion/duplicates).

### 1.3 Architecture
```mermaid
graph TD
    Physical_Disk[/dev/sdb] --> VG[LVM VG: ha_pool]
    VG --> LV1[LV: vol_mysql]
    VG --> LV2[LV: vol_nfs]
    LV1 --> DRBD1[Resource: res_mysql]
    LV2 --> DRBD2[Resource: res_nfs]
```

## 2. Module: Data Migration Engine (🟡 Partial)

### 2.1 Overview
Migrates existing services (e.g., `/var/lib/mysql`) to HA storage with minimal manual intervention.

### 2.2 Implementation Details
- **Core Logic:** `src/core/data_migration.rs`
- **Status:** **Cold Migration** is fully implemented.
- **Workflow (Implemented):**
    1.  **Stop Service:** `systemctl stop <service>`
    2.  **Promote DRBD:** `drbdadm primary <res>`
    3.  **Format:** `mkfs.<type>` (if requested)
    4.  **Mount:** Temporary mount at `/tmp/drbd-migrate-...`
    5.  **Sync:** `rsync -avH...` from source to DRBD.
    6.  **Demote:** `drbdadm secondary <res>`
    7.  **Restart:** `systemctl start <service>`

### 2.3 Pending Features
- **Live Migration (Pre-Copy):** The initial design included a "Pre-Copy" phase (rsync while service runs) to minimize downtime. This is currently **TODO**.
- **Rollback:** Automated rollback on failure is partially covered by error handling, but complex state recovery needs testing.

## 3. Module: NFS High Availability (✅ Core Implemented)

### 3.1 Overview
Provides Active-Passive NFS export with VIP and state persistence.

### 3.2 Implementation Details
- **Core Logic:** `src/core/nfs.rs`
- **Generator:** `NfsGenerator` creates `ocf:heartbeat:exportfs` resource strings.
- **State Handling:** `setup_nfs_state` function implements the critical logic of moving `/var/lib/nfs` to the shared DRBD storage (`.nfs_state` directory) and symlinking it back. This ensures NFS locks and client states are preserved during failover.

### 3.3 Configuration
- **Reactor:** Uses `ocf:heartbeat:exportfs` to dynamically manage exports.
- **Systemd:** `nfs-server` binds to the mount unit.

## 4. Module: iSCSI High Availability (✅ Core Implemented)

### 4.1 Overview
Exposes DRBD-backed volumes as iSCSI Targets with VIP.

### 4.2 Implementation Details
- **Core Logic:** `src/core/iscsi.rs`
- **Generator:** `IscsiGenerator` generates `targetcli` command sequences.
- **Workflow:**
    1.  Create Backstore (Block).
    2.  Create Target (IQN).
    3.  Create Portal (VIP binding).
    4.  Map LUNs.
    5.  Set ACLs.
- **Service Orchestration:** Rely on `drbd-reactor` to execute these commands or manage a `target.service` wrapper.

---

## 5. Module: NVMe-oF High Availability (✅ Core Implemented)

### 5.1 Overview
Exposes DRBD volumes via NVMe over Fabrics (TCP/RDMA) for high-performance workloads.

### 5.2 Implementation Details
- **Core Logic:** `src/core/nvmeof.rs`
- **Generator:** `NvmeOfGenerator` generates `nvmetcli` command sequences (or direct configfs interactions).
- **Workflow:**
    1.  Create Subsystem (NQN).
    2.  Create Namespace (mapped to DRBD device).
    3.  Create Port (VIP binding, Transport type).
    4.  Enable Port.
